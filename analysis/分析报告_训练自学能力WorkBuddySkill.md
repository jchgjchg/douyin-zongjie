## 一、核心结论（一句话）

真正的自学能力不是"会做题"，而是**掌握一套"把问题变成专属 skill"的方法**——用 WorkBuddy（对话式 AI 工作台）+ IMA（个人知识库）把你的痛点拆解成可复用的工具、流程和规划，再用 PBL 思路把这套方法论迁移到任何学科。作者原话："你一旦学会了这种方法……你就永远会自学了。"

---

## 二、关键概念

### 1. PBL（Problem-Based Learning，基于问题的学习）
- 不是"先学知识再做题"，而是**从你真实遇到的问题出发**，为这个问题定制 learning 方案。
- 视频主张：如果每门学科你都为自己碰到的每个 problem 做一套基于它的 learning 方案，你就等于"把家底（能力）码（码住/攒下）"了。

### 2. 为什么要做"自己的 skill"
- 作者比喻："只有你自己定做的衣服穿得才舒服。"
- 别人做好的 skill 可以给你用，但**真正的能力是"你会不会反向破解、做成你自己的东西"**——所以视频最后让家长/孩子根据谈话过程自己复刻，而不是单纯下载。

### 3. 与主播"三性"聊天原则
和 AI 聊天写 skill 时，记住**三性**：**逻辑性、科学性、全面性**。用自然语言慢慢修正，不达意就接着聊。

## 三、核心方法论：用 WorkBuddy 做一个专属 skill（五步）

以"高三数学 110 分左右、被压轴题（小压轴/大压轴）折磨"为案例，作者演示了完整流程：

| 步骤 | 做法 | 要点 |
|------|------|------|
| **① 定义角色 + 描述现状** | "我是一名高三学生，数学 110 左右（满分 150），总复习中" | 先让 AI 知道你是谁、水平在哪，后续产出才能"量身定造" |
| **② 讲清旧方案痛点** | 原来用**高拍仪**把不会的题拍下来，分别投喂给豆包、千问、元宝等独立大模型，看它们意见是否统一来判断标准答案 | 繁琐、要一个个复制粘贴（Ctrl+V）投喂，效率低 |
| **③ 提"多快好省"的新需求** | 让 WorkBuddy：a. 清晰拍摄原题；b. **由它挑选队员组成讨论小组**（找最适合的大模型）；c. "不要担心算力"（用户会付费）；d. 要"意见一致的答案和过程"或"投票比例"；e. 能数形结合的尽量用数形结合（调用 GeoGebra 类矢量工具）；f. 结果可选择存电脑或 IMA 资料库 | 把"分别投喂"升级为"AI 自动组队背靠背解题 + 投票裁决" |
| **④ 让 AI 复述需求 + 追加要求** | 怕没听懂，先让它复述；确认后追加：每道题做清晰标签和命名 | 命名规范本身就是一种知识管理 |
| **⑤ 落成专属 skill** | 问"上述要求能否形成我专用的 skill"，确认后开干；并考虑"如何让同学也能享受我的劳动成果" | skill 可分享，但强调"自己定做"才是真学会 |

### WorkBuddy 的三种模式（作者原话，对应产品内的工作模式）
1. **开干（直接干活）**：一次性把问题全描述清楚，它就开始干。
2. **问（只问不动手）**：只提问，不执行。
3. **计划 / Plan（边聊边想）**：边聊边构思，**你不下命令它不动手**——适合先把方案聊透再执行。

> 注：这是视频作者对 WorkBuddy 模式的口语化归纳，与产品内置的 Agent/Plan/Ask 等模式理念一致，命名以作者原话为准。

## 四、产出示例："高中数学·破阵子" skill

作者用几十道压轴题测试后，以一道为例展示 skill 的产出（他给自己这个 skill 取名"破阵子"，借词牌名）：

- **skill 全称**：高中数学破阵子 · 多模型讨论组判决
- **案例题**：圆锥曲线压轴题，被命名为"椭圆轨迹与中心对称分类"
- **运作方式**：
  - 组长（WorkBuddy）挑选 3 个"最能干"的大模型当队员，**背靠背**独立解题；
  - 组长收卷看三方意见：一致就直接给；不一致由组长**调意见到一致**——省去你一个个投喂的麻烦；
  - 本题三问投票均 **3:0 一致**，自信度"无限接近 100%"。
- **给你的不是答案，是"破题口"**：作者特地要求"不要给过程、不要给调整答案，用一句话人话讲破题口"——让你水平够、看到一句话就知道会做了。
- **数形结合动态提示**：凡能数形结合的，用数形结合动态解决圆锥曲线问题（如最后一问"t 为何值是双曲线/椭圆"）。
- **得分点清单**：列出 11 个得分点，漏拿会扣过程分。
- **知识点归因 + 易错提醒**：小组长带开会，给出考点、破题钥匙、4 个易错小点。
- **组长审稿小结**：类似作者此刻对观众做的"审稿小结"。

## 五、能力迁移（这条最值钱的部分）

作者强调：学会"把问题变成 skill"的方法论后，要**在学科间迁移**——

- 文言文碰到问题 → 能不能编一个 skill？
- 英语长难句（字幕音译"长蓝句"）读不懂 → 能不能用这套方法编 skill？
- 英语读后续写拿不到 20 分以上 → 能不能编 skill？

核心：**方法论可迁移，具体 skill 要自己定做**。会为每门学科的每个 problem 做基于它的 learning 方案，就是"把家底码住了"。

## 六、可信度与适用评估

- **可信度：高（方法层面）**。WorkBuddy、IMA、GeoGebra、豆包/千问/元宝均为真实可识别产品；"多模型投票裁决""量身定造破题口""数形结合提示"是合理且可落地的 AI 工作流设计；PBL 是成熟教育方法论。
- **适用边界 / 提醒**：
  - 视频是**教学演示**，强调"思路"而非承诺分数。把"投票一致"等同于"标准答案概率高"在数理化中通常成立，但**大模型仍可能集体出错**，关键步骤仍需人（或老师）复核——作者也要求呈现"得分点""易错提醒"正是为了让人把关。
  - "不要担心算力（我会掏钱）"提示该流程依赖付费 API，成本非零。
  - 转写里有若干音译已修正：whatbody/Wordity→**WorkBuddy**；ima/I'ma/艾玛/海拙→**IMA**（腾讯个人知识库类产品）；小亚洲大亚洲→**小压轴大压轴**；竖型/竖形结合→**数形结合**；圆椎→**圆锥**；长蓝句→**长难句**；"iMac 资料库"疑为 **IMA 知识库**。"Tera"为视频中作者对 AI 助手/对话对象的称呼，保留原样。

## 七、给 Jim 的落地建议

这条跟我们**正在用的 WorkBuddy** 直接对应，可立即复用：

1. **把你反复做的事沉淀成 skill**：比如你现在的"抖音视频→转写→分析"流水线，本质就是一个可固化的 skill（事实上已存在于 `~/.workbuddy/skills/douyin-transcribe-analyze`）。下次遇到新重复任务，先想"能不能让 WorkBuddy 帮我做成专属 skill"。
2. **用 Plan 模式先聊方案**：复杂任务别直接"开干"，先切计划模式把流程聊透，再下命令——跟作者"不下命令不动手"一致。
3. **用"三性"写需求**：跟 AI 提需求时自觉带**逻辑性、科学性、全面性**，并让它先复述再执行，能大幅减少返工（我们第 33–51 批就是靠"硬化分析 Prompt + 复述校验"把报告质量拉起来的）。
4. **多模型交叉验证**：涉及事实/数学/代码的关键结论，学作者的"投票裁决"思路——让多个模型背靠背给答案，一致才采信。
