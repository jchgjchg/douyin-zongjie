## 3. 关键操作要点（按章提取，避坑优先）

### 第 1 章 · 安装与建库（最重要：防丢笔记）
- **下载**：官网安装包托管在 GitHub（音译"gethub"），国内直连难；作者给的国内加速入口为 `Obsidian.xxx.cn`（音译"赵祖明.cn"，疑为 obsidiancn.com 类镜像）+ 某知识库（音译"飞出知识库"，提供安装包与插件加速），由"笔记同步科技"公司提供。
- **Windows 千万别装 C 盘**：重装系统即没；Mac 可放 iCloud（需先手机开通 Obsidian 应用专属文件夹）或桌面"Obsidian 仓库"文件夹。
- **丢笔记只有三种原因**（作者原话）：①库放 iCloud 到期没续费被删 ②库放桌面/C 盘被清理软件删 ③库放在 Obsidian 软件目录下、软件一更新被删。**避开这三类就不会丢**。

### 第 2 章 · 界面
- 编辑区三种模式：**实时预览**（默认，推荐）/ 源码模式（科技佬用）/ 阅读模式。
- 标签页可拖成左右/上下分屏、堆叠；**工作区核心插件**可保存布局下次恢复；独立窗口适合沉浸写作。

### 第 3 章 · 文件管理（理解"AI 搭档"基础）
- Obsidian 笔记库就是一个文件夹，.md 与电脑文件一一对应——"这就是为什么 Claude Code / Codex 等 AI 智能体能直接操作 Obsidian 笔记"。
- `.obsidian`（音译"DiorObsidian"）隐藏文件夹存所有配置（快捷键/主题/插件/排版）。想换整套配置：复制该文件夹到新库即可。
- **数据本地化本质**：不用了删掉配置，库就是纯净 Markdown 文件库——"这就是 AI 时代的最优解"。

### 第 4 章 · 笔记属性
- 第一行打三个短横（`---`）激活；类型含别名/标签/打卡(复选框)/日期/日期+时间/列表/数字/文本。
- 用途：数据库和 AI 按属性检索；**文本属性写一句话简介，AI 直接读简介不必读完正文**（省 token）。
- 右侧边栏可批量重命名某属性（如所有"打卡"→"跑步"）。

### 第 5–6 章 · Markdown 语法
- **段落分隔必须空一行**（否则双链会误判整篇为一个段落）。
- 强调层级：高亮=重点，加粗=强调，斜体=某名词/人（或用双链代替）。
- **制表符(Tab)陷阱**：中文用户想"首行缩进"按 Tab，实际是建代码块而非缩进（Markdown 规定）——用列表的缩进代替。
- 标题最多六级；超三级建议拆成卡片笔记。
- 高级语法（表格/图表/公式/嵌入视频/HTML）作者明确说"正常知识管理完全用不到"，要哪个现学哪个；图表公式让 AI 生成代码粘贴即可。

### 第 7 章 · 双链（核心能力）
- **Wikilink**（`[[笔记名]]`）：Obsidian 专属、最方便；**标准 Markdown 链接**（`[名](路径.md)`）：通用、迁移不掉链。
- **与 AI 适配的关键**：赛博永生 AI 知识库里用标准 Markdown 格式 + **完整相对路径**写双链，AI 扫到路径直接读对应笔记；不写路径则全盘扫描同名笔记，效率低。
- 附件拖入即双链；图片前加 `!` 显示；可指定宽高、PDF 页码。

### 第 8–9 章 · 设置（作者花了 19 分钟，比插件两章还长）
- **外观**：主题社区（作者爱 minimal）；CSS 让 AI 写；界面/正文/代码字体分开。
- **钥匙串**：可存 AI 的 API 密钥（但作者不建议在 Obsidian 放隐私，密码管理用 1Password（音译"ePassword"，付费零事故））。
- **编辑器**：默认实时预览；开"限制行宽"（沉浸码字）；开"折叠标题/缩进参考线"；关"严格换行"。
- **文件与链接（最实用）**：
  - 新建笔记存放位置 → **当前所在文件夹**（双链建的笔记自动归到项目文件夹，免二次移动）。
  - 附件默认路径 → **当前文件所在文件夹下的子文件夹"附件"**（迁移项目时附件一起打包）。
  - 内部链接 → **基于仓库根目录的绝对路径**（人/AI 一眼知来源）。
  - 回收站 → 关"删除前确认"（每天删太多）；删附件"每次都询问"（防误删其他笔记引用的附件）；删文件"移系统回收站"（留后悔药）。

### 第 10 章 · 核心插件（原生 20+）
- **命令面板**（Cmd+P）：最常用，可置顶命令。
- **反向链接**：右侧栏显示所有连到当前笔记的链接。
- **数据库**（今年新推，多维表格）：按规则检索，非常强。
- **搜索**：强但学习成本高；模糊概念交给数据库/AI。
- **日记**：独立体系，配合每日复盘。
- **工作区**：保存布局快速切换。
- 作者泼冷水：**关系图谱"用处不大、只提供情绪价值"**；**幻灯片"鸡肋"**（有空让 AI 生成更好）；**录音机/漫游笔记**几乎不用。

### 第 11 章 · 第三方插件（"非折腾不可才装"）
- **BRAT**（音译"B-R-A-T"）：下载未上架市场、GitHub 开源的插件/主题。
- **Git**：版本控制/备份（作者厘清"同步≠备份"：同步会双向删，备份是定时上传云端可恢复；U 盘/时间机器/NAS 都行）。
- **图床**：粘贴图上传图床返链接，省本地空间、方便分享（Cloudflare（音译"Cloudfair"）几乎免费）。
- 列表增强 / 外链一键 / 最近文件 / 光标回位 / 路径显示 / 主题增强 / **Linter(自动化脚本)** / **Templater(模板+脚本)** / **Tasks** / **Dataview(大缸优化器)** / **Excalidraw(EGO 素材管理，重度附件囤积者方案)**。
- 作者预防针：**"折腾插件可以，但必须建立在非折腾不可；否则只是浪费时间，知识一点没积累"**。

## 4. 作者反复强调的底层认知

1. **数据本地化 = AI 时代最优解**：Obsidian 所有内容都是本地 .md，配置在 `.obsidian`，删配置即纯净文件库。
2. **AI 搭档定位**：纯 Markdown 让 AI/人都易读；给 AI 喂"原始笔记 + 属性简介"而非总结；用完整路径双链让 AI 精准定位。
3. **三个笔记库分层**（整门课至少用三个）：①练手库（用完删）②以人为本个人知识库 ③**赛博永生笔记库**（专门给 AI 增改读写）。
4. **不要过度美化**：知识管理目的是完成工作/学习，不是把笔记做好看；HTML/CSS 美化让 AI 写即可。

## 6. 与 #57《别再吹 Obsidian，该从 AI Agent 淘汰》的观点碰撞

这两条正好打对台，但细看**并不真正矛盾**，而是互补：

- **#57 的核心批评**：①"第二大脑"论不成立（双向链接只是文字连文字）②给 AI 喂"结论总结"而非"原始过程日志"会漏掉隐含意图（红烧肉菜谱类比）③AI 无遗忘、多副本会让 Agent 混淆。→ 主张 Obsidian 该淘汰。
- **本视频的反驳/印证**：①通篇论证 Obsidian 是**本地 .md 编辑器**，纯文本最利于 AI 读——恰好规避 #57 说的"喂结论"问题（本视频要求存**原始笔记+属性**，不是总结）②提出"赛博永生笔记库"专门给 AI 增改读写，用**完整路径双链**让 AI 精准定位——正面解决了 #57 担心的"多副本混淆"③"数据本地化是 AI 时代最优解"直接回敬 #57 的"淘汰论"。
- **结论**：两者共识其实是"**给 Agent 喂原始过程/原始文本，别喂二次加工总结；可复用方法抽成 skill**"。分歧只在 #57 措辞极端（"Obsidian 是垃圾/该淘汰"），本视频用 88 分钟证明 Obsidian 作为**本地纯文本库**在 AI 工作流里仍有明确价值。**对 Jim 的建议**：个人思考/写作可用 Obsidian；但别把它当"喂给 Agent 的第二大脑"——你现在的 `analysis/`+`downloads/`+`memory/` 体系（原始稿+总结分离）本身已是更优的"赛博永生库"雏形。

## 7. 与你的关联 / 落地建议
