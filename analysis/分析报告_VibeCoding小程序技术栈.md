# 分析报告：Vibe Coding 技术拆解——小程序技术栈怎么选

> 来源：抖音视频 https://v.douyin.com/sVUbHbmJ_zw/ （时长约 6 分 17 秒）
> 类型：技术教程 / Vibe Coding（小程序开发 · 前端选型）

## 1. 一句话核心
小程序前端别纠结，无技术背景、全靠 AI 写代码就直接上 UniApp，并一开始就让 AI 留好多端后路。

## 2. 内容结构与要点
- **背景陷阱**：对 AI 说"帮我做个小程序"，它甩出一串名词（原生 / UniApp / Taro），你可能连用的哪套都没搞清项目就开了——而且挑的这套可能根本不适合你。
- **小程序三层**：用户点的界面（前端）、背后数据与逻辑、怎么上线；本集只解决第一层"界面用什么框架搭"。
- **前端三条路**：①原生=各平台官方写法（微信 / 支付宝 / 抖音各写一套，绑定单平台）；②UniApp=Vue 写法，一套代码发多端；③Taro=React 写法，一套代码发多端。
- **直接给答案：UniApp**。理由三：社区最活跃、坑都有人踩过解、AI 最会修；留后路（以后扩支付宝 / 抖音 / H5 / APP 改改就能上，不用重做）；现成轮子多（下拉刷新、日历、地址选择、轮播、表单控件生态成熟，不用让 AI 手搓易出 bug 的小控件）。
- **原生 / Taro 何时上**：原生=只做一个平台且要把性能压榨到极致才考虑；Taro=本身就会 React，否则没必要。
- **最值钱动作**：从第一行代码起就交代 AI"后期可能扩端，尽量用跨端通用写法、少用平台专有 API、必须用时单独标出"——避免多端能力被悄悄写死。
- **AI 还会挖的坑**：推已停更老框架（mpvue / WePY，等于房子盖在没人管的地基上）；放着成熟插件偏自己临时拼（后面各种报错的源头）。避坑三动作：让 AI 说清框架 / 插件是否主流、还在维护、最近有无更新；分清官方生态成熟方案 vs 它自己临时拼的（后者警惕）；听不懂就让它大白话重讲，别记个名词就往下走。
- **选完框架别急开搭**：先立规矩（设计风格、目录规范、UI 组件库、设计 Token 统一）再写功能，下一集专门拆。

## 3. 关键概念 / 模型解析
- **跨端框架（UniApp / Taro）**：用 Vue / React 一套代码编译到微信、支付宝、抖音等多平台，省去逐端重写；代价是多一层抽象，出问题也多一层。
- **mpvue / WePY**：早期小程序 Vue 系框架，均已停更，新手易被 AI 误荐踩坑。
- **设计 Token**：统一颜色 / 间距 / 字体等设计变量的规范，让 AI 每次产出风格一致，是"先立规矩"的技术落点。

## 4. 观点与可信度评估
- **高可信**：三种框架事实准确（UniApp=Vue、Taro=React、原生=平台官方写法），跨端能力、社区活跃度、避坑建议（别用停更框架 / 先立规矩 / 听不懂就问）均符合工程常识，实用性强。
- **中可信（立场鲜明）**："无脑推 UniApp"对纯新手最稳，但原生在官方支持、性能上限，Taro 在 React 团队里也各有优势；作者为降低决策成本有意简化，非绝对真理。
- **总体**：面向"无技术背景、全靠 AI 写代码"人群的小程序前端选型教程，结构清晰、可操作，适合 Vibe Coding 新手照做；属观点输出而非官方标准。

## 5. 实战建议
1. **开项目第一句就给 AI 加约束**："用 UniApp，后期可能扩端，尽量跨端通用写法、少用平台专有 API，必须用时单独列出"——这句最值钱，从根上保住多端后路。
2. **让 AI 自报家底**：框架 / 插件是否主流、在维护、最近更新；遇它自己拼的组件要警惕，优先用官方生态成熟方案。
3. **选完框架先立规矩再开搭**：设计风格 + 目录规范 + 组件库 + 设计 Token 先固化，别一句"开搭吧"放任 AI 乱架，越往后越难收拾。
